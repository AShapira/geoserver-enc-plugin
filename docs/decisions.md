# Design and implementation decisions

## 2026-11-13 — initial architecture

1. Target GeoServer **3.0.2 / GeoTools 35.2 / Java 17+**, pinning matching versions. The official release page lists these as the current stable line. Other versions require rebuilding and testing, not dropping mismatched GeoTools JARs into the server.
2. Implement a discoverable, read-only GeoTools DataStore plugin. Use GDAL's S57 driver via `ogr2ogr` to create an indexed GeoPackage snapshot. This isolates GDAL native code from the servlet JVM, avoids JNI ABI coupling, and makes repeated WMS/WMTS requests independent of S-57 parsing cost. This is a GDAL-backed S-57 store, not a new S-57 parser.
3. One store per ENC cell. Expose object-class feature types, retaining source attributes and geometry. GeoServer provides WMS; integrated GeoWebCache provides WMTS for an ordered chart layer group. Multi-cell quilt selection and overlap suppression are outside the initial implementation.
4. Apply adjacent updates; split SOUNDG multipoints and retain depth. Do not silently skip failed features. Fingerprint the complete base/update chain and GDAL version; atomically publish immutable cache generations. A store is a snapshot: reload/recreate it after updates, then invalidate its tile cache. Do not change datasets underneath open JDBC readers.
5. S-57 specifies data encoding; **S-52** is the portrayal target. Reuse attributable OpenCPN S-52 lookup/symbol resources where possible, preserving their license and provenance. Record unsupported conditional symbology explicitly. Do not claim ECDIS conformance without the complete conditional procedures and IHO S-64 tests.
6. Use a real NOAA cell downloaded from the current individual ENC catalogue. Keep raw chart data, runtime downloads and generated caches out of source control; record hashes and provenance. No claim of currency after the recorded download.
7. S-62 is a producer-code register, not an ENC encoding. Preserve `AGEN` and `LNAM`; document producer enrichment plus a separate S-63 authorized decryption design (if that was intended), and S-101 future architecture.
8. Launch local tools and a dedicated loopback GeoServer within this workspace. Do not modify existing containers/services or workstation system packages. All significant later changes and test results are appended here or in `validation.md`.

Sources: [GeoServer release](https://geoserver.org/release/3.0.2/), [release matrix](https://github.com/geoserver/geoserver/wiki/Release-Schedule), [GDAL S57](https://gdal.org/en/stable/drivers/vector/s57.html), [IHO standards](https://iho.int/standards-and-specifications), [NOAA individual ENCs](https://charts.noaa.gov/ENCs/ENCsIndvDole.shtml), [OpenCPN vector portrayal](https://opencpn.org/wiki/dokuwiki/doku.php?id=opencpn:manual_advanced:charts:vector_palette).

## 2026-11-13 — implementation and runtime findings

9. The plugin JAR depends on GeoTools `gt-geopkg` as **provided**; GeoServer 3.0.2's tested distribution already includes it. No shaded GeoTools or GDAL JNI libraries are packaged. Native import is an argument-list subprocess with timeout, combined diagnostics and no shell interpolation. Only administrators configure executable/source paths.
10. GeoTools `ContentFeatureSource` wraps the GeoPackage reader, so writable feature stores never escape through the public S-57 API. Query filtering, sorting, paging and projections delegate to JDBC; native regression tests cover these behaviors. DSID remains in the cache but is excluded from spatial feature types.
11. Set `LIST_AS_STRING=ON` for S-57 enum lists; preserve relationship arrays as strings and remove output field-width limits to avoid truncation. Assign new GeoPackage feature IDs because split soundings share source identifiers; retain LNAM/RCID for provenance.
12. Snapshot identity is SHA-256 over a shared versioned recipe, GDAL version, canonical source path, filenames and complete base/update bytes. Imports serialize within the JVM, use per-key file locks across processes, detect source changes during conversion, and atomically move complete snapshots into place. Readers never see partial files. Old generations are intentionally retained.
13. **Observed GDAL pitfall:** renaming the real NOAA `.001` update to `.002` allowed a successful conversion that silently skipped that update. Import now queries GDAL's exported DSID_UPDN and compares it with the highest sidecar number. Mismatch and cancelled edition 0 fail before publishing the cache. Reissued base cells with a nonzero UPDN and no sidecars remain valid. A regression test reproduces the gap.
14. S-52 lookup rules are compiled into mutually exclusive SLD filters; geometry PRIM distinguishes mixed geometry classes. Styles are split into global display-priority passes because a single style per object class cannot preserve cross-class draw order. Unknown/missing symbology is reported. The compiler uses no executable catalogue instructions.
15. Atlas pivots are preserved using transparent bitmap padding because SLD 1.0 Graphic lacks an AnchorPoint. HPGL rendering supports the commands actually present in the pinned line/pattern catalogue; tests render all its vector definitions and bitmap patterns. Regular spacing and joins remain approximations.
16. Choose fixed palette/safety presets per chart group. This gives explicit WMTS cache identity without conflating arbitrary WMS ENV requests. The publisher configures 4×4 metatiling/64-pixel gutters and truncates both configured tile grids on updates. Every published palette must be regenerated after a cell/settings change.
17. **Observed GWC API behavior:** JSON GET→PUT round-trip of the layer configuration failed with duplicate `metaWidthHeight` fields. Use XML for GWC configuration. Its default Web Mercator grid is named `EPSG:900913`; use that exact identifier for WMTS matrices and cache truncation. WMS supports EPSG:3857.
18. NOAA US5NY1AI (a real base plus `.001`) exercises update handling. US5NY1BH (coastal bays near Jones Inlet) provides richer visual review: 40 portrayed classes and 55 global style passes in the initial tested preset. Every download gets an immutable hash-named extraction directory and a provenance manifest.
19. Added exact Linux conda package URLs/hashes plus checksummed micromamba and GeoServer downloads for reproducibility. Runtime resides under `.runtime`; source/portrayal resources, scripts, test code and decisions accompany the binary archive. No existing workstation/container services were modified.
20. Retain the distinction between passing protocol/query tests and portrayal conformance. Current remaining conditional-procedure and cartographic gaps are documented in `portrayal.md`, with S-62 metadata, S-63 authorized import and S-101 decoder/portrayal suggestions in `future-formats.md`.
21. The portrayal publisher rejects non-metre depth units rather than labeling feet/fathoms as metres. Publication/catalog changes and tile truncation are administrative operations, not one atomic transaction; immutable source/cache generations do not imply an atomic multi-palette catalog switch. For uninterrupted production updates, publish a new versioned workspace, validate it, switch clients, and retire the previous workspace after readers finish. Updating an existing workspace can retain obsolete individual feature types; the regenerated chart group includes only current portrayed classes.

## 2026-11-15 — container deployment and full NOAA catalogue

22. The prior process was alive inside WSL, but Windows could not reach the WSL loopback listener. Move deployment to a detached, rootless Podman container built **FROM the official vanilla `docker.osgeo.org/geoserver:3.0.2`**. Add only GDAL/Python tooling, fonts, the plugin JAR and its publisher. Use named volumes scoped to this demo, a health check and `unless-stopped`; do not touch unrelated containers. Test access from Windows as well as Linux. The container's IPv4 loopback port publication restored Windows localhost forwarding; the private WSL address was blocked, so the final configuration publishes only loopback. No firewall or port-proxy changes are required.
23. Extend the plugin with a `catalogue` parameter, mutually exclusive with `file`. A prepared SQLite inventory includes every active cell, its relative source path, actual GDAL M_COVR coverage, edition/update, compilation scale, available contours, class counts and unified schemas. Source files reside in an immutable archive-hash directory. Catalogue preparation fails if any active cell is missing or does not match the advertised edition/update; cancelled cells are excluded. Native GDAL opens/apply-updates are validated for every active cell during indexing.
24. Load a spatial STRtree over individual coverage components, avoiding all-world envelopes for multipart dateline coverage. Use the WMS scale denominator to exclude excessive detail (`view scale > 4 × compilation scale`, with overview charts retained for context). Sort eligible cells by detail, then usage band and deterministic cell ID. Subtract higher-priority coverage from coarser cells globally, before object-class selection, to prevent a missing class in a detailed chart from leaking a coarser chart's objects. This is a documented scale-selection heuristic, not full ECDIS chart selection.
25. Open GDAL-to-GeoPackage cell caches on demand, retain a bounded lease-counted LRU of JDBC stores, and stream per-cell queries through each spatial index. Schemas/counts/bounds come from the inventory, so publishing the national store does not scan millions of features. Prefix feature IDs with cell ID and expose `_enc_cell`, `_enc_cscl`, and each cell's selected `_enc_safety_contour`. Unscaled WFS queries expose source features; WMS queries use the quilt. Raster rendering remains in vanilla GeoServer/GWC.
26. Retain S-52 lookup generation but compile against the union catalogue schema and order all class/style passes globally. Use per-cell safety-contour selection instead of assuming one contour inventory for the entire country. Store setting `safetyDepth` and generated style settings must agree. The earlier one-cell-only limitation is superseded by this catalogue store; remaining portrayal limitations are still recorded separately.
27. **Live national-overview regression found and fixed:** The datastore looked up a lowercase key in `EnvFunction.getLocalValues()`, whose keys are normalized to uppercase. The first full-US render consequently used scale 0 and selected 5,303 overlapping cells. Correct the fallback key and add a standard `GetMapCallback` bean that captures the normalized rendering scale before rendering and clears its thread-local state on success/failure; this also covers GWC internal renders. Do not infer scale merely from BBOX width or arbitrary client ENV values. Add callback cleanup and live overview regression coverage. Cache each opened cell's immutable snapshot path for the store lifetime, avoiding repeated GDAL version subprocesses when LRU entries are reopened.
28. The container build compiles this plugin against the **unmodified official GeoServer image's own libraries** in a separate build stage, then copies only the plugin into the runtime image. No host JDK/Maven installation or prebuilt plugin binary is required for `container/demo.sh`. Maven remains the source test/package build. Both Docker and Podman build contexts exclude runtime downloads, data and credentials.
29. The container demo includes a self-contained viewer at `/enc.html`, loading OpenLayers from GeoServer's bundled assets. Region bookmarks, day/dusk/night palettes and WMS/WMTS switching exercise one national catalogue rather than separate per-region stores. All 7,114 active cells were additionally preconverted in the container with GDAL 3.8.4; every applied edition/update and GeoPackage integrity check passed. Retain the complete inventory report and cache-warming report as evidence.
30. **Axis-order regression:** at the callback stage, WMS 1.3.0 EPSG:4326 still has north/east axes. Calling the map-content scale API directly selected different cells from an equivalent WMS 1.1.1 request. Normalize a private map-content copy to east/north before calculating catalogue scale; leave the actual request untouched. Use `CRS.lookupIdentifier`, because under GeoServer's `forceXY=true`, `CRS.toSRS` can produce an axis-strict URN that overrides `decode(..., true)`. Run tests with the same forceXY property and an actual URN CRS. Add a non-square image regression and require pixel-identical live outputs for equivalent axis orders. Preserve GeoServer's requested scale-computation method, DPI and map rotation in this copy. Cell selection alone was insufficient: the original `wms_scale_denominator` still changed SCAMIN styling between axis orders. Supply the normalized value through `enc_scale_denominator` for the generated ENC styles, with the standard WMS variable as a fallback. Do not overwrite the scale environment used by unrelated styles. Clear the ENC value on completion/failure.
31. Catalogue availability does not imply every cell is drawn at every zoom. Retain the explicit four-times-scale cutoff; do not force harbour geometry into continental views to hide overview coverage gaps. Record these gaps and the remaining conditional portrayal limitations instead of claiming full ECDIS selection or conformance. All source cells remain available when zoomed to an eligible scale.
32. A final restart test exposed a transient rootless Podman/pasta port-release race. Allow the old listener to exit and start the same container again; do not kill unrelated listeners or change Windows forwarding/firewall settings. The subsequent start retained all catalogue/configuration/tile volumes. Record the retry in validation rather than claiming the initial immediate restart succeeded.

## 2026-11-15 — measured S-52 portrayal improvements

33. Use **actual, unmodified OpenCPN 5.12.4** as a reproducible visual reference in an isolated Ubuntu/Xvfb container. Do not substitute an invented nautical mockup or call the result an IHO reference-ECDIS test. Match individual NOAA cells, chart updates, viewport, palette, safety settings, display category and SCAMIN. Capture full screenshots and saved configuration; retain UI masks and comparison formula. Test the national quilt independently because its cell-selection policy differs from OpenCPN.
34. Match OpenCPN's projected viewport using its Mercator scale factor 0.9996 and use WMS `SCALEMETHOD=Accurate` for the comparison. Keep generic GeoServer/WMTS scale semantics unchanged. Record both requested precise coordinates and OpenCPN's rounded saved coordinates. Use one chart per reference workspace; three source cells cover New York soundings/palettes, an extinguished California light and active Humboldt sector lights. US5CA6EE includes updates .001–.004; its reference log confirms target final update 4.
35. Port the metre branch of SNDFRM02 and ranked RESTRN/RESARE and TOPMAR procedures from the pinned OpenCPN release. Register a GeoTools `ExternalGraphicFactory` for `image/x-enc-s52` and custom text functions through normal SPI, preserving the vanilla GeoServer image. A reserved `file:/enc-s52/` URL carries evaluated attributes and is an identifier only; the implementation never opens it. Bundle the atlas/XML/license resources in the plugin JAR using Maven/container build resources and retain upstream attribution in NOTICE.md.
36. Use a 512-entry LRU for compound icons and fixed canvases around the actual S-52 pivot. Soundings combine individual digit/quality/drying glyphs; lights use a larger 200 px canvas. Cache keys include palette and all supplied portrayal attributes. The icon cache bounds only plugin-held icons, not total JVM/renderer memory. Recognize the atlas light flare as already oriented at 135 degrees; applying another 135-degree rotation was caught in the reference comparison and corrected before the final capture.
37. Separate RESTRN from RESARE. An absent RESTRN emits no restriction symbol or boundary; RESARE retains its own boundary and category/restriction symbol ranking. Do not infer a warning merely because a class has a conditional procedure. Integer-list parsing treats 1 and 11 distinctly. Unit tests cover empty attributes and competing restrictions.
38. The remaining magenta coast clutter came from **shared-edge priority**, not just RESTRN. Add lazy per-cell coastline/construction context and a synthetic `_enc_line` for RESARE, CTNARE, CBLARE, PIPARE and ACHARE. Remove exactly coincident COALNE/SLCONS segments from their boundary lines while preserving source polygons and feature attributes. Clip the derived line independently during national quilting so clipped polygon edges do not invent chart-boundary strokes. Cache derived lines by class/feature within the leased cell. This is a targeted approximation, not full S-57 primitive-edge priority or MASK support; some reference magenta edges remain missing.
39. Resolve TOPMAR floating parents with a lazy per-cell index of co-located BOY*, LITFLT and LITVES points, rounded to 1e-7 degree. Expose `_enc_floating` without rewriting the immutable GDAL cache. Default to a fixed parent when no floating parent is found. Enriched feature readers defer filtering/sorting/projection/pagination to the ContentDataStore wrappers, so virtual attributes remain queryable. Close context readers before opening feature readers to avoid exhausting a small per-cell JDBC pool.
40. Compile TX/TE formatting, colour, justification, offsets and weight; normalize body size against OpenCPN's default 10 pt chart font at 96 dpi. Retain GeoServer's label collision engine. Larger text improves size fidelity but changes which labels fit; the daytime global pixel MAE worsened even though some feature errors improved. Document this explicitly rather than selecting only favourable metrics.
41. Honour a vector pattern's definition even if a bitmap preview also exists. Apply its specified minimum spacing at the reference pixel density and build two-row tiles for staggered patterns. This fixes the overly dense marsh rendering. Pattern origin/clipping phase and complex-line corners still differ. Add dredged-area fills/patterns and attribute-based point-wreck symbols/depth/Wk labels; keep isolated-danger and general obstruction gaps explicit.
42. Preserve all pre-existing immutable GDAL snapshots and the full 7,114-cell catalogue. Native portrayal enrichments operate on the existing cache recipe; no nationwide reimport or destructive cache migration is needed. Republish all day/dusk/night groups and invalidate their generated tiles. Keep named volumes and unrelated services intact. Reference OpenCPN does not become a runtime dependency of the GeoServer image.
43. Profile the live Java process with JFR and sample container cgroup CPU/memory plus Java RSS/I/O. Baseline geometry predicates repeatedly rebuilt topology state; use prepared immutable coverage geometries and enlarge the coverage-selection LRU from 24 to 128 because style buffers generate many viewport keys. The geometry-only before/after PNG hashes were identical. Latency improved in those samples; CPU results did not establish a causal saving.
44. Keep warm WMS, WMTS MISS/HIT, four-request concurrency and idle measurements separate. Do not flush shared host caches. Report CPU relative to one core, distinguish RSS/heap/container file cache, and separate image layers from named-volume storage and development downloads. Repeat the final warm benchmark and report variability. Exclude the JFR diagnostic run from performance claims because profiling and concurrent development work changed its CPU/timing. Richer portrayal adds cost in some regions, especially San Francisco; do not claim an overall speedup.
45. Recommend selective WMTS preseed and disk quotas first, then versioned native-edge metadata and reduced repeated feature/filter work. Worker/heap/container-limit changes remain suggestions until sustained load tests justify them. No host tuning, CPU affinity, memory cap, global pruning or unrelated service changes were performed. Keep six-scene comparison evidence and nine-region protocol checks alongside the design log and distributable source.

## Optimization implementation — 2026-11-16

46. Replace the runtime five-class `BoundaryContext` approximation with native, per-cell shared-edge metadata. Reconstruct Edge endpoints from ConnectedNode, retain ordered FSPT orientation/usage/MASK and spatial quality, and resolve ownership among visible line-drawing features. Preserve original polygon geometry and keep coverage quilting separate. Remove the obsolete overlay class and its approximation-only test; add native topology/mask/orientation/SCAMIN regression tests.
47. Version sidecars independently of immutable GeoPackage snapshots. Hash the import identity plus a portrayal recipe/XML revision, validate updates and source stability, use process file locks and atomic publication, and support bounded administrative prewarm. The first ownership recipe incorrectly treated filled DEPARE polygons as line owners; correct that before final validation and bump the recipe. Retain the superseded generated sidecars as a separate, explicitly counted development generation rather than silently overwriting them or pruning persistent storage.
48. Precompute the ordered S-52 lookup RCID using the same attribute/null/list rules as the SLD compiler. Publish integer `_enc_lookup` filters while keeping SCAMIN and conditional expressions dynamic. Push native BBOX filters down before enrichment. Cache assembled edge chains in an estimated 4 MiB LRU per retained cell, keyed by feature and effective SCAMIN band. Raw topology maps remain governed by cell-store lifetime. Do not introduce an additional cache of mutable, viewport-clipped feature objects without evidence that its memory/copying cost is justified.
49. Enforce a fair four-render admission limit for ENC WMS and internal WMTS renders, with a 30-second queue timeout and release on success, failure or request reinitialization. Use a 6 GiB container allowance around the existing 3 GiB heap. Keep the cell-pool target at 32 and avoid host CPU affinity or global tuning. A render permit is not a limit on all HTTP request preparation or total JVM memory.
50. Apply a 2 GiB GeoWebCache LRU quota, checked every 60 seconds by one cleanup worker, seven-day server tile expiration and one-hour client expiration. Use production logging and a 120-second WMS rendering timeout. Verify settings through REST read-back. GeoServer 3.0.2's quota GET exposes bytes but PUT requires value/units; use the documented PUT representation, not a blind round-trip of GET XML. The quota is an asynchronous tile-cache target, not a hard cap on all application storage.
51. Seed only New York and San Francisco operational extents at zooms 11–13 in three palettes. Calculate an upper bound including complete 4×4 metatiles (816 tiles for this plan), reject plans above the explicit cap, run one job at a time and fill missing tiles rather than reseeding everything. Save configuration and per-job checkpoints. Keep nationwide harbour-scale seeding outside the default workflow.
52. Repeat actual OpenCPN captures for all six scenes using the same three NOAA cells and numbered updates; verify their hashes and retain requested/actual display settings. Capture fresh baseline GeoServer images before replacement. Keep the November 15 evidence intact. Measure visual differences against the newly captured reference and report regressions as well as improvements; pixel agreement is not an S-52 compliance score.
53. Benchmark initial and warm WMS, WMTS MISS/HIT, four-request concurrency and sustained eight-client load separately. Do not run imports, image builds or OpenCPN during the final measured workload, and do not drop workstation OS caches. Record cgroup CPU/memory, Java RSS/I/O and heap. Fix benchmark cleanup to stop its sampler inside the container: terminating only the local Podman client left old sampling processes alive. The replaced baseline container contained these lightweight samplers; disclose this small idle-CPU confound.
54. The reference harness must separate chart-database rebuilding from the screenshot run. OpenCPN's rebuild intentionally moves own-ship to the selected chart centroid. Restart after rebuilding, set own-ship to 1N/1E outside all three scenes, and capture without a forced rebuild. Wait for process exit before reading saved settings. Verify actual settings and retain both initial and final requested configurations. This avoids comparing a vessel overlay that GeoServer does not render.
55. Report the final result as a topology/precomputation and cached-delivery improvement, not a blanket WMS speedup. Two warm five-call passes straddle the baseline; CPU cost also varies with pass/JVM state. Preserve initial-request timings separately and make no cold-storage claim. The initial 160-request/eight-client test lasts about one minute, yields p95 3.10 seconds and 2.66 requests/s, and has identical PNG hashes with no errors; it is not an indefinite soak or all-viewports capacity guarantee.
56. Audit all 7,114 final sidecars independently: 4,148,511 edges, 3,854,646 native feature lookup records, 13,965,547 links, zero integrity/reference errors and zero unmatched lookups. Verify every one of the 246 requested seed tiles as a HIT. Keep the superseded development sidecar generation separate in disk accounting: current metadata costs 2.31 GiB, and the retained superseded generation costs another 2.31 GiB.
57. Validate the render admission limit with a separate diagnostic thread dump (four waiting requests during an eight-client run), not only a semaphore unit test. Exclude JFR/thread-dump timings from throughput claims. Export execution samples at stack depth 128 to avoid the JFR printer's shallow default. Geometry clipping/predicates and JDBC/decoding remain hotspots; measure a bounded immutable geometry cache and JDBC metadata reuse before adding another feature cache. Keep conditional priority promotion and spatial-quality portrayal as explicit remaining fidelity work.
58. Restart verification exposed a GeoWebCache 2.0.2 REST defect: quota PUT mutates the bean but does not save/reload it. Confirm against the installed bytecode and upstream controller. Persist the quota XML through GeoServer's data-directory resource API, reload the dedicated server, and verify again after container recreation. Rerun performance tests with the persisted quota active; retain earlier runs separately. This workaround changes no vanilla GeoServer/GWC library.
