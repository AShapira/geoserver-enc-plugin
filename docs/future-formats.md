# S-62, S-63 and S-101 extension options

## S-62 producer metadata

[IHO S-62](https://registry.iho.int/producercode/list2.do) registers producer identifiers. It does not define an ENC file encoding. This plugin already preserves S-57 `AGEN`, `LNAM`, `LNAM_REFS`, and `FFPT_RIND`; the cache's `DSID` table retains `DSID_AGEN`. The NOAA samples identify producer 550.

Suggested addition: import a versioned CSV export of the IHO producer register, retaining its download date and checksum. Resolve `AGEN` to producer name/country for GetFeatureInfo and layer metadata. Keep numeric source identifiers unchanged, retain unknown codes, and avoid making live register availability a prerequisite for map rendering. Add tests for unknown, retired, and changed producer codes. No additional chart reader is required.

## S-63 encrypted ENC support plan

**Recommendation, 22 November 2026.** For an air-gapped installation receiving encrypted S-57 exchange sets, pilot **SevenCs Nautilus ChartServer** locally and publish its rendered charts through GeoServer. For a connected viewer, pilot **PRIMAR Web Chart Service** or **ADMIRALTY Vector Chart Service (AVCS) Online**. If the requirement is to use this plugin’s own portrayal, spatial filters or feature layers, first investigate a **derived-product data licence**. These are proposed integrations for shore-based GIS. Encrypted S-101 uses the separate S-100 Part 15 scheme. [IHO protection schemes](https://iho.int/en/enc-data-protection-s-57)

### Why the existing importer needs a different input

`enc deploy` copies the whole exchange directory, builds a catalogue and retains per-cell GeoPackages and SQLite edge databases. GeoServer can expose the resulting features through WFS, and GeoWebCache can retain their rendered tiles. The IHO OEM agreement permits temporary clear data during conversion and requires its removal after success or failure. It also requires protection of the internal system ENC (SENC). A decrypt-to-directory step feeding the existing cache would leave portable chart copies. Keep permits and protected exchange sets outside the ordinary staging path. ### Pilot and release criteria

1. **Select one area and one use case.** For an offline pilot, obtain an evaluation runtime and a distributor-issued base cell plus an update for the test installation. For hosted WMS, obtain an evaluation account covering the same area if available. Ask for separate prices for the software, chart subscriptions, server instances and end users. Record whether imagery, picking, tiles and vector delivery are permitted, along with the rules for expiry, retention and failover. A cell permit authorizes decoding for a particular installation. Serving its contents to other users requires the corresponding rights.
2. **Publish one authenticated WMS layer.** For a local chart server, use a dedicated GeoServer workspace and an external WMS store. For a hosted provider with per-user tokens, use a server-side adapter that binds identity to each entitled request, renews tokens and keeps credentials out of URLs visible to users, capabilities and logs. Extend the viewer’s source entry with the actual layer, supported palettes, attribution and supported operations. Start with uncached images, restrict picking to licensed fields and disable feature downloads. The viewer discovers published S-57 layer names through WMS. [Viewer](../src/main/resources/enc/viewer/index.html) · [Source publication](../scripts/publish.py)
3. **Verify chart and access behaviour.** For local import, run the IHO S-63 test cases for the chosen component and a supplier exchange set. Verify the issuer and cell signatures, wrong-installation and missing permits, out-of-sequence updates, reissue and cancellation. Record cell ID, edition, applied update and outcome. A failed update must leave the previous authorized edition identifiable and issue a visible warning. For either WMS route, compare a known sounding and aid to navigation with the provider’s reference at two scales. Test two users with different coverage, denied picking, expiry, restart, and upstream unavailability. For the offline route, repeat import and rendering with outbound networking disabled. [IHO test data and guide](https://iho.int/en/enc-data-protection-s-57)
4. **Enable caching only under agreed terms.** Apply access checks before every cache hit, including direct GeoWebCache endpoints. If WMTS is licensed, isolate tiles by entitlement, chart generation and portrayal. Apply supplier rules separately to update eligibility and continued display of installed editions. When display rights end, block output immediately and expire all affected caches and replicas on the agreed schedule. Verify that restoring an older generation cannot restore revoked access. Release the selected route after both the chart-update and access tests pass.

## S-101 / S-100

S-101 is a different ENC product model with separately versioned feature and portrayal catalogues. The [IHO product resource page](https://iho-ohi.github.io/S100Resources/) publishes these resources; [IHO's product-specification overview](https://iho.int/en/s-100-based-product-specifications) explains their relationship.

Keep a decoder boundary separate from portrayal: a future `S101Importer` should preserve S-100 feature associations, complex attributes, catalogue version, vertical reference and coverage metadata in a suitable indexed model. Add an S-100 portrayal engine for its catalogue and conditional rules. The existing Java DataStore serving pattern and GeoServer protocols are reusable, but the S57 GDAL driver and this S-52 lookup compiler are not a complete S-101 implementation. A controlled S-101-to-S-57 conversion could be a limited migration route, only with an explicit loss report and validation. Reader availability and catalogue compatibility must be verified against the chosen future library/version.
